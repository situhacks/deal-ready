# Two substrates, same corpus, same ground truth

**Run 2026-09-01.** The repo can read a CIM two ways. This measures both on the twenty
chart-carried values in the corpus — the only surface where they could possibly differ, because
the text layer already recovers every prose and table metric at 100% on both paths.

| | Local path | Plugin / agent path |
|---|---|---|
| Reader | `glm-ocr` 0.9B parser + `qwen3.8:27b` chart specialist + pixel geometry | frontier vision model, one page at a time, following `cim-read` |
| Runs on | the operator's GPU, no network | any agent session, no clone, no models |

## Accuracy — chart-carried values only, n = 20

| Read type | n | Local | Agent |
|---|---|---|---|
| Printed chart labels (`label`) | 10 | **10/10** | **10/10** |
| Measured off the axis (`axis`) | 10 | **10/10** | **10/10** |
| **Total** | **20** | **20/20 (100%)** | **20/20 (100%)** |

Every value exact — zero difference, not "within tolerance". The full per-value table is below.

**Text-layer metrics were not re-tested** because Layer P already establishes both paths recover
prose at 100% and tables at 100%; they read the same extracted text. Across all ten rubric
metrics on all five targets, both substrates therefore recover 50/50.

## The finding is that accuracy is not the differentiator

**This corpus cannot separate the two substrates on correctness.** Both are perfect, so anything
that distinguishes them has to be something else:

| | Local | Agent |
|---|---|---|
| Latency, 1 target, warm cache | **2.6s** | seconds per page, 2 pages read |
| Latency, text layer only | 0.4s | n/a |
| Latency, cold (no cache) | ~100s across the 5-target corpus | same order; not separately measured |
| Marginal cost per document | electricity | tokens |
| Needs | a GPU and three pulled models | nothing |
| Reproducible offline by a third party | **yes** — `run_checks.py` re-measures the axis values from committed pixels with no GPU and no model | **no** — needs a model with vision |
| Failure mode | fails loudly: a page that yields no values is reported unresolved | fails like a model: a confident wrong number is possible |

**The reproducibility row is the one that matters.** A number the local path produces can be
re-derived by anyone, on any machine, forever. A number the agent path produces cannot be — it
can only be re-run. For a screen a deal lead may have to defend a year later, those are not the
same property.

## Honest limits

- **Twenty values, one synthetic corpus, one run each.** Not a general result about either
  reader.
- **The corpus is favourable.** It was generated by this repo from known values and rendered
  cleanly at 120 dpi. Real CIMs are scanned, skewed, compressed, and occasionally hostile. **A
  100% here does not predict 100% there**, and the `realworld/` manifest exists precisely because
  this corpus cannot answer that question.
- **Ground truth is a by-product of generation**, not independent labelling. A generator and a
  scorer written in the same repo are favourable to each other by construction.
- **The agent-path latency and cost columns are indicative, not instrumented.** No token counter
  was attached.
- **The two readers were not run under identical conditions.** The agent read one chart page at a
  time with the `cim-read` instructions in context. The bake-off's 80%-on-axis figure for
  `qwen3.8:27b` was measured differently — as a full-page reader over a whole document — so the
  older table row and this one are not a like-for-like model comparison.
